## The moves

### Truth sprint: fix the map's factual misencodings and lock them with data tests
Why: These are the first things a foreign-affairs reader checks, and each one contradicts ATLAS's only real moat. Embeds and PNGs carry them onto third-party sites. Most fixes are S data or pipeline changes; one schema field is M. Nothing else has as much impact per hour.

What: Day one: rewrite the Legend.tsx:295 note to say what is actually drawn, and change the dossier badge to 'Party to: High'. Then add an optional `theatre: Iso3[]` to ConflictInput and schema.ts (iran-israel [IRN,ISR], yemen [YEM], hormuz [], south-china-sea [], and so on). Build maxIntensityByCountry from theatre only and draw parties fighting abroad as a dashed outline, with a matching legend row. In build-sanctions.mjs, route the UKR and MDA EU regimes into a `concerns` array. Drop UNHCR 'UNK' rows so Kosovo stops showing 1.8M displaced, and add the PSE UNRWA/OCHA series with a 'known source gap' hatch. Add an 'occupation' presence kind (UKR←RUS, LBN←ISR) and refile the PRK troops under RUS. Scope the relationship section to 'US and EU sanctions' with a not-in-scope empty state. Carry forward missing years in blocTrend so GCC/OPEC stop showing a 2025 collapse. Add a SOVEREIGN map so Greenland inherits NATO. Guard all of it in data.test.ts: theatre ⊆ countries, UKR and MDA have 0 targeting regimes, PSE is never bin 0, displacement ≤ population, GCC's last point is within 5% of the previous one.

## How to work
1. `git fetch origin main && git checkout -b claude/review-truth origin/main`, then `pnpm install`.
2. Verify each issue still reproduces before fixing it (the review ran against main at commit 81bae1e). Fix the root cause the recommendation names; where a recommendation is a sketch, use judgement and keep the change proportionate. Every ref must end up fixed, or explicitly deferred with a reason in the PR body.
3. Add or update tests for what you change: unit/data tests in vitest (`src/**/*.test.ts`), and update `e2e/smoke.spec.ts` where behaviour intentionally changes. Never delete or skip a test to get green.
4. Before every push run `pnpm check` (typecheck + lint + vitest + build) and `pnpm run build && PW_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome pnpm run test:e2e`. Look at the result in a real browser (Playwright screenshots of the states you changed, desktop and phone, dark and light) before calling it done.
5. Generated data files (`*.generated.json`, `public/feed.*`) come from their scripts — regenerate with the `pnpm run data:*` script rather than hand-editing; if the network blocks a source, make the script change, keep the committed file consistent, and say so in the PR.
6. Commit in logical steps. Push with `git push -u origin claude/review-truth`.
7. Open a pull request against `main` titled `Review batch 1: Data truth sprint`. Body: one section per move, a checklist of every issue ref (fixed / deferred + why), before/after screenshots where visual, and test notes. Then subscribe to the PR's activity and drive it to green: fix CI failures, address review comments, and when `main` moves (other batches merge) merge `main` into your branch and resolve conflicts carefully, keeping both sides' intent. Do not merge the PR yourself.
