## The moves

### Make the map's state visible and every overlay dismissible
Why: Layers silently override mode, bloc and compare while the chips and panel claim the old view. The bloc panel's primary 'Show on map' button is a no-op. On 1280x720 the layer menu runs off screen, so Displacement can't be switched off. Three 'reset' controls exist and none of them resets. Users can't tell what they are looking at.

What: Add a map-state strip above the legend, e.g. 'CONFLICTS › OVERLAY: SANCTIONS › REPLAY MAR 2026 › FOCUS: SUDAN', with a ✕ per segment and a Reset button. Add a ✕ to the legend h3. The LayerMenu trigger becomes a text button ('SANCTIONS ▾'). The menu measures available space, caps max-height, and uses native radios in a fieldset. Bloc chips render muted while a layer is on, and picking a chip or 'Show on map' clears the layer. Chokepoints over Blocs falls back to neutral land. In Conflicts mode, append an intensity key under every layer legend. The brand mark becomes a true reset, and ⌂ becomes an SVG 'Reset zoom'. Split map-controls into Data, View and Share groups; the Share popover holds Copy link, Copy embed code, Export PNG and Present.

### Quick win: Layer menu fits every screen and the legend can clear a layer
Measure the space above and below the button, set an inline max-height with overflow-y:auto, and hide hints under max-height:760px. Add a ✕ to the legend title that sets layer:null, so turning a layer off never depends on the menu.

## How to work
1. `git fetch origin main && git checkout -b claude/review-mapstate origin/main`, then `pnpm install`.
2. Verify each issue still reproduces before fixing it (the review ran against main at commit 81bae1e). Fix the root cause the recommendation names; where a recommendation is a sketch, use judgement and keep the change proportionate. Every ref must end up fixed, or explicitly deferred with a reason in the PR body.
3. Add or update tests for what you change: unit/data tests in vitest (`src/**/*.test.ts`), and update `e2e/smoke.spec.ts` where behaviour intentionally changes. Never delete or skip a test to get green.
4. Before every push run `pnpm check` (typecheck + lint + vitest + build) and `pnpm run build && PW_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome pnpm run test:e2e`. Look at the result in a real browser (Playwright screenshots of the states you changed, desktop and phone, dark and light) before calling it done.
5. Generated data files (`*.generated.json`, `public/feed.*`) come from their scripts — regenerate with the `pnpm run data:*` script rather than hand-editing; if the network blocks a source, make the script change, keep the committed file consistent, and say so in the PR.
6. Commit in logical steps. Push with `git push -u origin claude/review-mapstate`.
7. Open a pull request against `main` titled `Review batch 8: Visible map state and dismissible overlays`. Body: one section per move, a checklist of every issue ref (fixed / deferred + why), before/after screenshots where visual, and test notes. Then subscribe to the PR's activity and drive it to green: fix CI failures, address review comments, and when `main` moves (other batches merge) merge `main` into your branch and resolve conflicts carefully, keeping both sides' intent. Do not merge the PR yourself.
