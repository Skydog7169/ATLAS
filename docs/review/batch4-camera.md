## The moves

### One footprint camera that knows what the panel or sheet covers
Why: Every selection type currently lands its subject out of view. ASEAN opens under the desktop panel, Sudan under the phone sheet, Mercosur outside the portrait crop. The pair view never moves, the globe resets to [15,20], and a 300x250 embed shows nothing. One fit function fixes phone, tablet, desktop, globe, briefing and embed.

What: Derive an inset {right, bottom} synchronously: useMediaQuery, plus a ResizeObserver on .panel, with a fallback of 0.52×innerHeight. Add Focus {kind:'isos'} that fits the union of members' largest-polygon bounds into the uncovered rect with k clamped to 1–6; when that can't work (Quad), show a '3 members outside view · Fit' chip. Use it in selectBloc, the chips, onVs (A∪B), briefing and selectPair. Pair fill: A = accent, B = warn, everything else dimmed. Conflict panels dim non-theatre countries. GlobeMap rotates to the footprint's geoCentroid and fits the visible band. The globe toggle uses focusForSelection instead of reset. Remove `features` from the fly-to dependencies to kill the double flight. Top-align land in the portrait initialTransform. Keep a recentre button above the phone sheet.

## How to work
1. `git fetch origin main && git checkout -b claude/review-camera origin/main`, then `pnpm install`.
2. Verify each issue still reproduces before fixing it (the review ran against main at commit 81bae1e). Fix the root cause the recommendation names; where a recommendation is a sketch, use judgement and keep the change proportionate. Every ref must end up fixed, or explicitly deferred with a reason in the PR body.
3. Add or update tests for what you change: unit/data tests in vitest (`src/**/*.test.ts`), and update `e2e/smoke.spec.ts` where behaviour intentionally changes. Never delete or skip a test to get green.
4. Before every push run `pnpm check` (typecheck + lint + vitest + build) and `pnpm run build && PW_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome pnpm run test:e2e`. Look at the result in a real browser (Playwright screenshots of the states you changed, desktop and phone, dark and light) before calling it done.
5. Generated data files (`*.generated.json`, `public/feed.*`) come from their scripts — regenerate with the `pnpm run data:*` script rather than hand-editing; if the network blocks a source, make the script change, keep the committed file consistent, and say so in the PR.
6. Commit in logical steps. Push with `git push -u origin claude/review-camera`.
7. Open a pull request against `main` titled `Review batch 4: Camera and mobile layout`. Body: one section per move, a checklist of every issue ref (fixed / deferred + why), before/after screenshots where visual, and test notes. Then subscribe to the PR's activity and drive it to green: fix CI failures, address review comments, and when `main` moves (other batches merge) merge `main` into your branch and resolve conflicts carefully, keeping both sides' intent. Do not merge the PR yourself.
