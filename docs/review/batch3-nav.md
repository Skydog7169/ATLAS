## The moves

### Navigation spine: real history, Escape, managed panel focus, and a camera that follows the URL
Why: Back exits ATLAS and throws away a chained exploration, which hurts most for people arriving from a shared link. Keyboard users are 36-60 Tab stops from the panel, and closing it drops focus to <body>. Related links silently change the user's lens with no undo. History makes Back the universal undo and takes the sting out of most side-effect complaints.

What: In useAppState, split push and replace. Push on selection, mode, bloc, vs, layer, view and brief changes. Replace for rotation and month scrub, committing one entry on pointerup. Add a fromHash ref so Back doesn't re-push. Replace the one-shot 'landed' effect with focusFromSelection() running on every hashchange. Add a usePanelFocus hook: focus the h2 (tabIndex=-1) on user-initiated opens, restore focus to the opener on close, set role=complementary with aria-labelledby, and remove aria-live. Add one app-level Escape that peels one layer at a time (picking, then panel); LayerMenu and Search call preventDefault. Closing a panel restores the pre-fly transform unless the user moved the map. Add panel=0 to the hash so a closed panel stays closed. Briefing snapshots and restores state. selectUnrest and selectChokepoint keep the user's layer. Add a '‹ Ukraine' back chip in the panel head.

### Quick win: Header panel buttons show when they are on
Style .header .icon-btn[aria-pressed='true'] with an accent outline and a 14% tint, so Changes, Watchlist and About visibly tie to their open panel.

## How to work
1. `git fetch origin main && git checkout -b claude/review-nav origin/main`, then `pnpm install`.
2. Verify each issue still reproduces before fixing it (the review ran against main at commit 81bae1e). Fix the root cause the recommendation names; where a recommendation is a sketch, use judgement and keep the change proportionate. Every ref must end up fixed, or explicitly deferred with a reason in the PR body.
3. Add or update tests for what you change: unit/data tests in vitest (`src/**/*.test.ts`), and update `e2e/smoke.spec.ts` where behaviour intentionally changes. Never delete or skip a test to get green.
4. Before every push run `pnpm check` (typecheck + lint + vitest + build) and `pnpm run build && PW_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome pnpm run test:e2e`. Look at the result in a real browser (Playwright screenshots of the states you changed, desktop and phone, dark and light) before calling it done.
5. Generated data files (`*.generated.json`, `public/feed.*`) come from their scripts — regenerate with the `pnpm run data:*` script rather than hand-editing; if the network blocks a source, make the script change, keep the committed file consistent, and say so in the PR.
6. Commit in logical steps. Push with `git push -u origin claude/review-nav`.
7. Open a pull request against `main` titled `Review batch 3: Navigation spine`. Body: one section per move, a checklist of every issue ref (fixed / deferred + why), before/after screenshots where visual, and test notes. Then subscribe to the PR's activity and drive it to green: fix CI failures, address review comments, and when `main` moves (other batches merge) merge `main` into your branch and resolve conflicts carefully, keeping both sides' intent. Do not merge the PR yourself.
