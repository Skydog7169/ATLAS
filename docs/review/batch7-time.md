## The moves

### Honest time: one as-of date that the map, panels, export and embed all read
Why: Replay currently asserts falsehoods (Iran 'latent' in Apr 2026). An out-of-range #t shows an empty world labelled DEC 2025. Exports and embeds present past states as current. Fixing time once at the state layer fixes five surfaces, and it is the second critical trust bug.

What: Clamp t in urlState parse() with an isValid.month validator: before the range snaps to Dec 2025 with a 'Replay starts Dec 2025' notice; the current month or later becomes live. Rewrite the hash. Timeline.tsx draws hollow ticks for months with no new assessment. Markers desaturate on those months, and the panel badge reads 'Last assessed 15 Dec 2025 · no assessment on record for Apr 2026'. Add an amber 'REPLAY · MAR 2026 · Return to live' banner, a month suffix on the legend title, and a 'Layer shows current data (fetched 8 Oct)' note. The export title, stamp and filename come from app state. The embed badge reads 'DATA OCT 2026' or 'REPLAY · MAR 2026'. Brand click and the Blocs toggle clear the month. Have the research pass backfill the Feb–Apr 2026 Iran war, Lebanon invasion and Hormuz closure entries.

### Quick win: Embeds stop trapping the page scroll
In embed only: touch-action pan-y pinch-zoom, ctrl/meta+wheel to zoom, two fingers to pan, with a 1.5s hint overlay. Anchor .map-controls at bottom:12px so the transparent strip stops blocking clicks. Drop the legend note pointing at bloc chips that embeds don't show.

## How to work
1. `git fetch origin main && git checkout -b claude/review-time origin/main`, then `pnpm install`.
2. Verify each issue still reproduces before fixing it (the review ran against main at commit 81bae1e). Fix the root cause the recommendation names; where a recommendation is a sketch, use judgement and keep the change proportionate. Every ref must end up fixed, or explicitly deferred with a reason in the PR body.
3. Add or update tests for what you change: unit/data tests in vitest (`src/**/*.test.ts`), and update `e2e/smoke.spec.ts` where behaviour intentionally changes. Never delete or skip a test to get green.
4. Before every push run `pnpm check` (typecheck + lint + vitest + build) and `pnpm run build && PW_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome pnpm run test:e2e`. Look at the result in a real browser (Playwright screenshots of the states you changed, desktop and phone, dark and light) before calling it done.
5. Generated data files (`*.generated.json`, `public/feed.*`) come from their scripts — regenerate with the `pnpm run data:*` script rather than hand-editing; if the network blocks a source, make the script change, keep the committed file consistent, and say so in the PR.
6. Commit in logical steps. Push with `git push -u origin claude/review-time`.
7. Open a pull request against `main` titled `Review batch 7: Honest time and embeds`. Body: one section per move, a checklist of every issue ref (fixed / deferred + why), before/after screenshots where visual, and test notes. Then subscribe to the PR's activity and drive it to green: fix CI failures, address review comments, and when `main` moves (other batches merge) merge `main` into your branch and resolve conflicts carefully, keeping both sides' intent. Do not merge the PR yourself.
