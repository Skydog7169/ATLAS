## The moves

### One theme-relative palette contract (palette.ts plus a validator test)
Why: Light theme is the default for every OS-light visitor, and it inverts every sequential ramp, so the first map they see reads backwards. The same root cause makes first bins invisible, makes conflict tints match no legend swatch and merge for deuteranopes, lets the vignette drop edge countries a class, and lets selection vanish on the cyan top step. One module fixes all of it.

What: Create palette.ts. Generate every ramp (OVERVIEW_STEPS, sanctions, displacement, elections, military) as color-mix(in oklab, hue N%, var(--land)) with evenly spaced lightness, following the trade.ts:47 pattern. Extract a conflictFill() used by both map and legend. Add a 'no data' hatch CountryFill with a legend swatch. Cap the overview top step below --accent. Draw selection as an overlay path with a 4px --bg + 2px --fg non-scaling stroke and delete the drop-shadow. Show hover as an outline, not a brightness filter. Move the vignette beneath the country paths, halve scanlines over land, and turn them off in light theme. The vitest should assert, in both themes, monotonic ΔL from land, ≥15 ΔE between adjacent bins, and CVD ΔE ≥12 for nuclear/umbrella and compare A/B (patterns where hue fails). Pin embeds to dark until this ships.

### Legibility pass: type tokens, a readable who-backs-whom graph, AA trust text, visible focus
Why: The headline 'who backs whom' graph renders at 4.6–5.8px for half the conflicts. The text that carries trust is the faintest in the app: --fg-faint at 3.4:1 in dark and 2.9:1 in light, set in 11px letter-spaced mono. The focus ring is clipped off every chamfered chip (WCAG 2.4.7). The token base makes all of this cheap.

What: Rebuild ActorsGraph as an HTML grid (repeat(auto-fit, minmax(160px,1fr))), with backers as ≥32px buttons that show the backed party and no character truncation. Add five type tokens (display, body, small, eyebrow, data) with floors: no mono under 11px, no sentence text under 12px, no tracking on prose. Set .updated in Rajdhani 12.5px --fg-muted. Use rem units and a stylelint floor. Token fixes: dark --fg-faint #6f90a8, light #4d6579, light --accent #07627f, --warn #8f5200, enforced by a tokens.test.ts asserting ≥4.5:1 in both themes, plus a pseudo-element-stripped axe pass. Inset focus rings on .chip and .text-btn, with a double ring on filled controls. Add a DataRow component with a fixed value column and intensity pills. Make trend charts full width.

### Quick win: Markers state their intensity; the page gets a proper outline
Marker aria-label and tooltip become 'Sudan civil war: high intensity', with the month added during replay. Tab order runs high intensity first. Replace role=application with role=group + aria-roledescription=map. Add an sr-only h1, make the legend title an h2, change section h4s to h3s, and move the eyebrow out of the panel h2.

### Quick win: Pulse only what matters
Restrict marker pulse rings to the selected conflict and to conflicts changed since the last visit. Give microstate squares a 1px 45% --fg stroke so they read as targets.

### Quick win: Remove the invisible blur and the layout-thrashing progress bar
Drop backdrop-filter from .panel, .legend, .timeline and .layer-list and use opaque --bg-elev. Animate .brief-progress with transform:scaleX instead of width. This roughly halves hover lag with a panel open and stops a wall display burning 30–40% of the main thread.

## How to work
1. `git fetch origin main && git checkout -b claude/review-palette origin/main`, then `pnpm install`.
2. Verify each issue still reproduces before fixing it (the review ran against main at commit 81bae1e). Fix the root cause the recommendation names; where a recommendation is a sketch, use judgement and keep the change proportionate. Every ref must end up fixed, or explicitly deferred with a reason in the PR body.
3. Add or update tests for what you change: unit/data tests in vitest (`src/**/*.test.ts`), and update `e2e/smoke.spec.ts` where behaviour intentionally changes. Never delete or skip a test to get green.
4. Before every push run `pnpm check` (typecheck + lint + vitest + build) and `pnpm run build && PW_CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome pnpm run test:e2e`. Look at the result in a real browser (Playwright screenshots of the states you changed, desktop and phone, dark and light) before calling it done.
5. Generated data files (`*.generated.json`, `public/feed.*`) come from their scripts — regenerate with the `pnpm run data:*` script rather than hand-editing; if the network blocks a source, make the script change, keep the committed file consistent, and say so in the PR.
6. Commit in logical steps. Push with `git push -u origin claude/review-palette`.
7. Open a pull request against `main` titled `Review batch 2: Palette contract and legibility`. Body: one section per move, a checklist of every issue ref (fixed / deferred + why), before/after screenshots where visual, and test notes. Then subscribe to the PR's activity and drive it to green: fix CI failures, address review comments, and when `main` moves (other batches merge) merge `main` into your branch and resolve conflicts carefully, keeping both sides' intent. Do not merge the PR yourself.
